# 計算するインクリメンタルゲーム（仮）

コアループ： **計算 → 報酬を得る → アップグレード → そしてまた計算**

**最終目標：1ラウンドの合計を 10^(10^100) より大きくすること。**

## 遊び方

`index.html` をブラウザで開くだけです（ビルド不要）。進行は localStorage に自動保存されます。

ローカルサーバーで開く場合は、同梱の開発用サーバーを使ってください。

```bash
python serve.py 8123
```

`python -m http.server` だとブラウザにキャッシュされて、直したのに画面が変わらない
ということが起きます（`serve.py` はキャッシュしないヘッダを付けて返すだけのものです）。
ファイルを直接開いている場合も、変更が反映されないときは Ctrl+Shift+R で再読み込みしてください。

## ウェブで遊ぶ

公開済み： https://claude.ai/artifact/VKtSb18RBV1wBQt2pKMWWh

## 画面の流れ

```
[① 計算] --3問解き終わる--> [② ラウンド結果] --「アップグレードへ」--> [③ アップグレード] --「計算に行く」--> [① 計算]
                                                                    └--「転生」--> [④ 転生] --「計算に行く」--┘
```

- 起動時は **計算画面だけ**（初回のみルール説明つき）
  - 上部に ①②③ のステップ表示。解くごとに ○ / × に変わり、右に「ここまでの合計」
  - 答えると式のカードが緑／赤に光り、○ × を 0.55秒 見せてから次の問題へ（`JUDGE_MS`）
  - 数字は3桁ごとにカンマ区切り。入力は全角数字・カンマ・空白も受けつける（`normalizeInput()`）
  - 入力はマウス（画面のテンキー）とキーボードの両方。テンキーを押してもフォーカスは入力欄に残る
- 解き終わると **結果画面**へ自動で切り替わる
  - 全問正解なら「パーフェクト！」バッジ
  - 正解した答えを足していく式 → 合計を1桁ずつ表示 → 「◯桁なので ⌊log10⌋ = ◯」
  - 獲得ポイントは 0 から数え上げ、自己ベスト更新なら表示
  - 「あと◯で桁が上がる」バーで次の目標が見える
- 「アップグレードへ」→ 強化と演算切替 → 「計算に行く」で自分のタイミングで次のラウンドへ

## いまのルール
## いまのルール

- 1ラウンドで **3問**（初期値）連続で解く
- **正解した問題の答えだけ**が合計に入る（`部分点` を買うと不正解の答えも一部入る）
- 報酬 = `( floor(log_b(合計) × 10) + 演算ボーナス + パーフェクトボーナス ) × 倍率`（端数切り捨て）
  - 例：合計 122 → `log10(122)` = 2.08 → ×10 して **20 T**
  - `× 10`（`REWARD_SCALE`）は報酬の**刻みの細かさ**です。これが無いと
    「桁が変わるまで1Tも増えない」ので、強化しても手応えが出ませんでした
  - 底 `b` は初期値 10（`対数の底を下げる` で変わる）
  - 演算ボーナス = 使用中の演算の種類 − 1（たし算だけなら 0）
  - パーフェクトボーナスは全問正解のラウンドのみ
- 初期状態は 1桁 + 1桁 のたし算のみ

### アップグレード（23種）

| 名前 | 効果 | 初期コスト | 上限 |
| --- | --- | --- | --- |
| 桁数アップ | 出題される数字の桁数 +1 | 5 T | 8桁 |
| 数字の直接指定 | 式の端数をきりよくして、計算を楽にできる | 50 T | — |
| ひき算 解放 | ひき算が出題に加わる | 25 T | — |
| 出題数アップ | 1ラウンドの問題数 +1 | 40 T | 8問 |
| 項数アップ | たし算の1問の数字の個数 +1（ほかの演算には効かない） | 60 T | 5個 |
| 報酬倍率アップ | 獲得Tポイント ×0.5 ずつ増加 | 75 T | Lv.20 |
| かけ算 解放 | かけ算が出題に加わる | 100 T | — |
| かけ算の項数アップ | かけ算の1問の数字の個数 +1（値段は4倍ずつ） | 150 T | 5個 |
| 部分点 | 不正解でも答えの 25 → 50 → 75% が合計に入る | 125 T | Lv.3 |
| パーフェクトボーナス | 全問正解のとき基礎値 +10 ずつ | 150 T | Lv.5 |
| わり算 解放 | わり算が出題に加わる（必ず割り切れる） | 200 T | — |
| べき乗 解放 | a^b が出題に加わる（答えの桁が一気に伸びる） | 1,500 T | — |
| べき乗の指数アップ | a^b の b の範囲が広がる（2〜3 → 3〜5 → …） | 750 T | **上限なし** |
| 対数の底を下げる | 基礎値が ⌊log₁₀⌋ → ⌊log₉⌋ → … → ⌊log₂⌋ に | 250 T | 底2 |
| 連続正解ボーナス | 連続正解1つにつき報酬 +5%（Lv×20 連鎖まで）。1問でも間違えると 0 に戻る | 1,000 T | Lv.5 |
| オート計算 | 出題された式を自動で解いてくれる（3.0秒に1問） | 1,250 T | — |
| 利息 | ラウンドが終わるたび、所持Tポイントが +2% ずつ増える | 1,500 T | Lv.10 |
| 一発勝負 | 1ラウンドの問題数を減らせる。1問減らすごとに報酬 ×1.3 | 2,000 T | — |
| 指数的報酬 | 報酬の基礎値そのものを 1.05 乗ずつ累乗する（桁が大きいほど効く） | 4,000 T | **上限なし** |
| オート速度 | 1問あたりの時間が ×0.8 ずつ短くなる（最速 0.5秒） | 750 T | Lv.8 |
| オート周回 | ラウンドが終わると自動で次のラウンドを始める | 5,000 T | — |
| 指数表記 | 数字が `m × 10ⁿ` の形で出題されるようになる | 10,000 T | — |
| 指数スケール | 出題される数字が `10^(n × 10^p)` 規模に。p は 1, 2, 4, 7, 11 … と跳ね上がる | 40,000 T | Lv.16 |

コストはレベルごとに増えます（桁数なら 5 → 15 → 45 → 135 …）。
表の値は `COST_SCALE`（いまは5倍）をかけたあとの、画面に出る値段です。
全問正解で進めた場合、**ほぼ毎ラウンド何かが買える**配分にしてあります
（R1 +16T→桁数、R2 +25T→桁数、R3 +36T→ひき算 …）。

`対数の底を下げる` は報酬式そのものを強化します。例えば合計1000なら
⌊log₁₀(1000)⌋ = 3 が ⌊log₂(1000)⌋ = 9 になります。

解放済みの演算は「使用する演算」でオン/オフを切り替えられます（最低1つは必要）。

## オート計算

`オート計算`（250 T）を買うと、計算画面の下に **オート計算** のスイッチが出ます。
入れておくと、出題された式を自動で解いて先へ進みます。

- `オート速度` で 3.0 秒 → 0.5 秒／問まで縮みます（`autoDelay()`）
- `オート周回` まで買うと、ラウンドが終わっても自動で次を始めるので放っておけます
- **アップグレード画面と転生画面を見ている間は自動で次のラウンドを始めません**。
  ゆっくり買い物できます（`autoStep()` の `isScreen()` 判定）
- スイッチの入/切はセーブされます。自分で解きたいときは切ってください
- オートが動いている間は ○× の表示時間も短くなります（`pause`）

## 育て方の分岐

中盤（200〜800 T）に、性質の違う4つの伸ばし方が並びます。全部は買えないので、
どれを軸にするかでビルドが変わります。

| 伸ばし方 | 何が起きるか | 相性 |
| --- | --- | --- |
| **連続正解ボーナス** | 正解を切らさないほど倍率が伸びる（最大 Lv×20 連鎖） | ミスしない**オート計算**と噛み合う。手動だと事故る |
| **利息** | ラウンドごとに所持Tポイントが増える。使わず貯めるほど効く | **オート周回**で放置するほど伸びる。買い物を我慢する必要あり |
| **一発勝負** | 1ラウンドの問題数を減らすほど倍率が上がる（1問減らすごとに ×1.3） | 合計は log なのであまり減らない。**短時間で回す手動**向き |
| **指数的報酬** | 報酬の基礎値を累乗する。基礎値 100 が 1.3乗で 398 に。**レベル上限なし**なので、伸ばし続ければ報酬そのものが桁違いになる | 序盤はほぼ無意味。**指数スケール**まで伸ばした終盤で化ける |

### 振り直し

ステータス欄の「**アップグレードを振り直す**」で、買ったアップグレードを白紙に戻し、
払った T ポイントが**全額返ってきます**（`doRespec()`）。
Σ・永続強化・これまでの記録は残るので、軸を変えて試すのは自由です。

返す額は `spentOnUpgrades()` が「まっさらな状態から今のレベルまで買った場合の合計」を
数えなおして求めるので、古いセーブでも正しく返ります。

なお「最初からやり直す」はセーブ全消し（Σも永続強化も消える）で、別物です。

`連続正解` と `一発勝負` は相反します（問題数を減らすと連鎖が伸びにくい）。
`利息` は買い物を我慢するほど強く、`指数的報酬` は先行投資が重いという具合に、
どれも「何かを諦める」形にしてあります。

## 式の数字を自分で書きかえる

`数字の直接指定`（10 T）を買うと、**計算画面**の式の下に「✎ 端数をきりよくする」が出ます。
押すと式が入力欄に変わり、出ている数字をその場で書きかえられます。
画面では「端数をきりよくして計算を楽にする」機能として案内しています。

```
 4,837 + 2,914     ←  ✎ を押す
[ 5000 ] + [ 3000 ]  ←  打ちかえて「この式にする」
 5,000 + 3,000
```

- 書きかえた式の答えは、その場で計算しなおされます（`evalProblem()`）
- 以降の問題も**同じ大きさ**で出るようになります（1つめの数字の桁から `state.manualLog` を決めています）
- 式の下の「自動に戻す」で、`桁数アップ` / `指数スケール` まかせに戻ります
  （いま出ている問題も作りなおします）
- 指数表記の数は `3e50` の形で書きかえます。15桁を超えると、`指数表記` が未解放でも
  自動的に指数表記で出題されます（`useSci()`）
- **上限があります**（`manualLimit()`）。アップグレードで出せる最大の大きさ ＋ 1桁ぶんまで。
  端数をきりよくしたり、ちょっと背伸びしたりはできますが、桁を飛び越えることはできません。
  超える値を入れると「いまは 100,000 までです」と出ます
- 値段はかかりません（`MANUAL_COST_RATE = 0`）。上限のほうで抑えています

### 壊れ具合を調整したいとき

- 上限の余裕は `manualLimit()`（いまは最大の +5%、整数のうちは +1桁）
- 値段を復活させるなら `MANUAL_COST_RATE` を `12` に（`manualCost()`）

## 桁の爆発と最終目標

`指数表記` を買うと、出題される数字が **m × 10ⁿ** の形になります。やることは変わりません。

```
(5 × 10^(6×10^106))^5   →  仮数 5^5 = 3125、指数 6×10^106 × 5 = 3×10^107
                        →  答え 3125e3e107   （= 3.125 × 10^(3 × 10^107)）
```

- かけ算 … 仮数をかけて、指数を足す
- たし算 … 指数をそろえて、仮数を足す
- べき乗 … 仮数を累乗して、指数をかける

数がどれだけ大きくなっても、手で解く計算は1桁どうしのままです。

`指数スケール` Lv.L で指数の規模 p は **1, 2, 4, 7, 11, 16 …（p = 1 + L(L+1)/2）** と跳ね上がり、
Lv.14 で p = 106、つまり 10^(n × 10^106) 規模の数字が出ます。ここで合計が **10^(10^100)** を超えます。

### 入力のしかた

`3e12` と書くと 3 × 10^12。指数自体も e 記法で書けるので `1e1e100` = 10^(10^100)。
指数表記を解放するとテンキーに `.` と `E` が出ます。入力欄の下に解釈結果が出るので確認できます。
`28e10` と `2.8e11` のように書き方が違っても同じ値として正解になります。

### 到達までの目安（直接指定を使わない場合）

全問正解で進めた場合のシミュレーションでは、
指数表記の解放が **約 185 ラウンド目**、指数スケールが 1レベルあたり 9〜10 ラウンド、
最終目標への到達が **約 465 ラウンド目** でした（転生を使えばもっと速くなります）。

## 転生（Σポイント）

アップグレード画面の「転生」から入ります。いままでの強化と所持Tポイントを手放して
最初からやり直し、かわりに **Σポイント** を受け取ります。

- 獲得Σ = 獲得Tが 100 を超えてから、**10倍になるごとに +4 Σ**
  （100 T で 1Σ、1,000 T で 5Σ、1,000,000 T で 17Σ …）
  終盤は獲得Tが 10^100 規模になるので、√ではなく log で数えています
- **累計Σ** 1つにつき報酬倍率 +10%（`Σの力` で最大 +100%）。Σを使っても累計は減らないので、
  ボーナスが下がることはありません
- 転生ボタンを押すと、その場に確認が出ます（はい／やめる）。
  ブラウザの `confirm()` は環境によってダイアログが出ないまま打ち消されることがあるので、
  **確認はページ内で完結させています**（「最初からやり直す」も同じ作りです）
- リセットされるもの：所持T・桁数・項数（たし算・かけ算）・出題数・倍率・対数の底・部分点・パーフェクト・演算の解放
  （`引き継ぎ` を買うと、このうち一部が残るようになります）
- 残るもの：Σ、永続強化、統計（累計獲得T・自己ベスト・転生回数）

### Σで買う永続強化

| 名前 | 効果 | 初期コスト | 上限 |
| --- | --- | --- | --- |
| 引き継ぎ | 転生しても残るものが増える（演算の解放 → オート一式 → 対数の底 → 報酬倍率） | 2 Σ | Lv.4 |
| 持ち込み資金 | 転生した直後に 10 → 100 → 1,000 … T を持って始める | 3 Σ | Lv.10 |
| 基礎値の底上げ | 報酬の**基礎値**に +1 ずつ（合計が小さいうちほど効く） | 4 Σ | Lv.10 |
| Σの力 | Σ 1つあたりの報酬ボーナス 10% → 25% → 50% → 100% | 3 Σ | Lv.3 |
| 英才教育 | 開始時の桁数 +1 | 2 Σ | Lv.7 |
| 予習 | 開始時の出題数 +1 | 4 Σ | Lv.5 |

**ねらい**：転生でいちばん痛いのは「積み上げた強化を失うこと」なので、
`引き継ぎ` で演算・オート・対数の底・倍率を残せるようにし、
`持ち込み資金` で再スタート直後から買い物ができるようにしています。
`基礎値の底上げ` は ⌊log(合計)⌋ そのものに足すので、小さい合計でも稼げるようになります。

永続強化は買った瞬間から今の周回にも反映されます（`applyPerm()` / `持ち込み資金` はその場で受け取れます）。

## 追加するときの勘所（`game.js`）

- **アップグレードを足す** → `UPGRADES` 配列に
  `{ id, name, max, level(s), cost(s), now(s), next(s), apply(s) }`
  を1つ追加するだけで、購入ボタンまで自動で生えます。
- **演算を足す**（累乗など） → `OPS` と `OP_ORDER` に定義を足し、
  `makeProblem()` に生成処理を、解放用のアップグレードを `UPGRADES` に追加。
- **報酬式を変える** → `rewardFor()` / `baseFromSum()` / `varietyBonus()` /
  `perfectBonus()` / `partialRate()` / `multiplier()`。
- かけ算・わり算は `safeProduct()` で桁あふれ（2^53 超え）を防いでいます。
  上限を超えそうなときは自動的に項を減らします。
- **T ポイントも巨大数**です（`state.points` / `runEarned` / `stats.earned` / `stats.best`）。
  小さいうちはふつうの Number のままなので、足し引きは `V.add` / `V.sub`、
  比較は `V.cmp`、割合をかけるのは `V.scale` を使ってください。
  `指数的報酬` に上限がないため、報酬は 1e308 を平気で超えます。
- **巨大な数** は `value.js` の `V` が扱います。値は「ふつうの Number」か
  `{ m, e }`（= m × 10^e）のどちらかで、小さいうちは Number のままなので整数計算は完全に正確。
  `V.add / mul / div / pow / eq / fmt / html / parse / tower` を使ってください。
  表示は `V.html()`（`<sup>` つき）、文字列は `V.fmt()`。
  指数は 2^53 未満なら省略せず正確に表示します（`+1` のズレを隠すと式が解けなくなるため）。
- **永続強化を足す** → `PERKS` 配列に追加し、必要なら `applyPerm()` に反映処理を書く。
  引き継ぎたい値は `doPrestige()` の `carried` に足す。
- **出題される数字の大きさ** は `intDigits()` / `randExp()` が決めています。
  `state.manualLog` が入っていればそれが優先されます。
- **画面を足す** → `index.html` に `class="screen"` の `<section>` を足し、
  `showScreen()` にその表示/非表示を1行追加。
- **セーブ項目を足す** → `newState()` に既定値を書けば、古いセーブは
  `load()` の `Object.assign` で自動的に補完されます。
  セーブ形式を壊す変更をしたら `SAVE_KEY` の末尾バージョンを上げてください。
